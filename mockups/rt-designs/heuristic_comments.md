# Add Word Record

## Cancel Button:

### **Heuristic 3: User Control and Freedom**

The previous draft did not have a clear visual to indicate how to return to the previous screen. The cancel button allows the user to exit the add word record menu and return to the previous screen.

## New Design

### **Heuristic 8: Aesthetic and Minimalist Design**

The previous design was clunky and gave equal weight to every widget by giving the word, origin, and definition text boxes the same dimensions. The new design puts most of the weight on the definition box as it is the biggest and most likely to contain the most words. The text box for word and origin are given the same weight.

## New webpage / popup

### **Heuristic 5: Error Prevention**

The previous design only focused on how users add a word record, but there was nothing about how users are meant to view or potentially edit a word record. Are users meant to reuse the same add functionality for editing and viewing? Are users expected to understand that the word "add" also means "save"? The answer to these questions are no. There are new wireframes for editing and viewing a word record to prevent any confusion with the application's design and/or functionality. 

The new view word record wireframe locks the text boxes so users can't edit them. If the user wishes to edit the word record, they can click the "Edit" button which will unlock the text boxes. 

## Hint text

### **Heuristic 10: Help and Documentation**

For adding a word, the previous design didn't have any hints for the text boxes. There are now hints in the input boxes for word, origin, and definition telling the user to enter the corresponding information in those text boxes.
